# useFindash Estoque Module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Estoque module — manual entry and management of devices (novo/seminovo) and accessories — as a deployable, testable slice at `/estoque`, per item 9 of the spec's "ordem de execução".

**Architecture:** Client components under `app/(dashboard)/estoque` and `components/estoque/*` call the Supabase browser client directly (matching the pattern already used in `app/(auth)/onboarding/page.tsx` and `app/(auth)/signup/page.tsx`), relying on RLS for tenant isolation. A new `getActiveStoreId` helper resolves the signed-in user's `store_id` client-side (same query middleware already runs) so every write can stamp `store_id`. Two new hand-authored shadcn-style primitives (`Badge`, `Select`) join the existing `Button`/`Input`/`Label`/`Card`, plus a `Dialog` primitive (Radix, new dependency) used both for create/edit forms and destructive-action confirmation, per the design system's "confirmação para ações destrutivas" requirement.

**Tech Stack:** Next.js 14 App Router + TypeScript (existing), Zod + React Hook Form (existing), `@radix-ui/react-dialog` (new dependency, same family as the already-installed `@radix-ui/react-label`/`@radix-ui/react-slot`), Vitest for pure-logic tests.

**Spec:** [docs/superpowers/specs/2026-09-22-usefindash-saas-design.md](../specs/2026-09-22-usefindash-saas-design.md)

## Global Constraints

- No IMEI lookup integration (spec section 7) — `imei` is a plain manually-typed field, validated only as 15 digits, never looked up against an external API.
- No billing/subscription/payment logic of any kind (spec sections 9, 12).
- `store_id` is the tenant isolation key; every insert/update must use the value from `getActiveStoreId`, never a value trusted from elsewhere in the client.
- RLS is already live on `products` and `accessories` (see `supabase/migrations/20260922100001_rls_and_functions.sql`): any store member can `select`/`insert`/`update`, but only `owner`/`admin` roles can `delete` (`products_delete`, `accessories_delete` policies use `has_store_role(store_id, array['owner','admin'])`). This plan does not add role-aware UI (no role is plumbed to components yet) — a `seller`-role user clicking "Excluir" will see the existing error state surface a generic failure message. That is acceptable for this slice; do not attempt to hide the button based on role in this plan.
- Design tokens and Tailwind class names from the Foundation plan are the contract — reuse `bg-background`, `bg-card`, `border-border`, `text-foreground`, `text-muted-foreground`, `bg-primary`/`text-primary`, `bg-secondary`, `text-success`, `text-warning`, `text-danger`. Do not invent new token names.
- `checkup_data`, `grade`, `suggested_price`, `final_price` on `products` are out of scope — this module never writes them (Checkup is the next module, item 10).
- `products.status` is only ever set to `available`/`reserved` by this module's UI. `sold` is set exclusively by the existing `mark_product_sold` trigger when a `sales` row is inserted (Vendas module, item 11) — never expose a manual "mark as sold" action.
- `products.days_in_stock` stays whatever the DB default/last cron run left it — the daily recompute cron is item 17, out of scope here.
- Live project: Supabase project `useFindash` (`crfmlimzjcztzlvylrpf`). `lib/supabase/types.ts` already has `products`/`accessories` `Row`/`Insert`/`Update` types generated from the live schema — import via `Tables<"products">` / `Tables<"accessories">` from `@/lib/supabase/types`, do not hand-write row types.
- Zod for all validation, React Hook Form for all forms (existing convention, e.g. `lib/validation/auth.ts`, `lib/validation/onboarding.ts`).
- Tests live in `tests/lib/**/*.test.ts` using Vitest (`npx vitest run`), matching `tests/lib/validation/auth.test.ts` and `tests/lib/auth/resolve-redirect.test.ts`. Pure presentational React components (Task 3's UI primitives, the list/dialog components in Tasks 5-6) follow the Foundation plan's Task 3 convention: no dedicated component test, verified instead via `npm run build` (type-checks + compiles) and manual smoke test in the dev server.

        path: ["imei"],

      });
    }
  });

```ts
import type { SupabaseClient } from "@supabase/supabase-js";

import type { Database } from "@/lib/supabase/types";

export async function getActiveStoreId(
  supabase: SupabaseClient<Database>,
  userId: string
): Promise<string | null> {
  const { data, error } = await supabase
    .from("store_users")
    .select("store_id")
    .eq("user_id", userId)
    .limit(1)
    .maybeSingle();

  if (error || !data) {
    return null;
  }

  return data.store_id;
}
```

      <div className="mb-4 flex flex-wrap items-end justify-between gap-4">
        <div className="flex flex-col gap-1">
          <span className="text-xs text-muted-foreground">Buscar por nome</span>
          <Input
            placeholder="Capinha, película..."
            value={nameFilter}
            onChange={(e) => setNameFilter(e.target.value)}
            className="w-56"
          />
        </div>
        <Button
          onClick={() => {
            setEditingAccessory(null);
            setFormOpen(true);
          }}
        >
          Novo acessório
        </Button>
      </div>

      {error && <p className="mb-4 text-sm text-danger">{error}</p>}

      {accessories === null ? (
        <div className="space-y-2">
          {[0, 1, 2].map((i) => (
            <div key={i} className="h-12 animate-pulse rounded-md bg-card" />
          ))}
        </div>
      ) : accessories.length === 0 ? (
        <div className="rounded-lg border border-dashed border-border p-8 text-center text-sm text-muted-foreground">
          Nenhum acessório encontrado. Cadastre o primeiro para começar.
        </div>
      ) : (
        <div className="overflow-x-auto rounded-lg border border-border">
          <table className="w-full text-left text-sm">
            <thead className="border-b border-border bg-card text-xs uppercase text-muted-foreground">
              <tr>
                <th className="px-4 py-3">Nome</th>
                <th className="px-4 py-3">Categoria</th>
                <th className="px-4 py-3">Quantidade</th>
                <th className="px-4 py-3">Custo</th>
                <th className="px-4 py-3">Preço de venda</th>
                <th className="px-4 py-3 text-right">Ações</th>
              </tr>
            </thead>
            <tbody>
              {accessories.map((accessory) => (
                <tr key={accessory.id} className="border-b border-border last:border-0">
                  <td className="px-4 py-3">{accessory.name}</td>
                  <td className="px-4 py-3">{accessory.category ?? "—"}</td>
                  <td className="px-4 py-3">{accessory.quantity}</td>
                  <td className="px-4 py-3">
                    {accessory.cost.toLocaleString("pt-BR", { style: "currency", currency: "BRL" })}
                  </td>
                  <td className="px-4 py-3">
                    {accessory.sale_price.toLocaleString("pt-BR", { style: "currency", currency: "BRL" })}
                  </td>
                  <td className="px-4 py-3">
                    <div className="flex justify-end gap-2">
                      <Button
                        variant="ghost"
                        size="sm"
                        onClick={() => {
                          setEditingAccessory(accessory);
                          setFormOpen(true);
                        }}
                      >
                        Editar
                      </Button>
                      <Button variant="ghost" size="sm" onClick={() => setDeletingAccessory(accessory)}>
                        Excluir
                      </Button>
                    </div>
                  </td>
                </tr>
              ))}
            </tbody>
          </table>
        </div>
      )}

      <AccessoryFormDialog
        open={formOpen}
        onOpenChange={setFormOpen}
        storeId={storeId}
        accessory={editingAccessory}
        onSaved={loadAccessories}
      />

      <ConfirmDialog
        open={!!deletingAccessory}
        onOpenChange={(open) => !open && setDeletingAccessory(null)}
        title="Excluir acessório"
        description={`Tem certeza que deseja excluir ${deletingAccessory?.name ?? "este acessório"}? Essa ação não pode ser desfeita.`}
        confirmLabel="Excluir"
        onConfirm={handleDelete}
        isConfirming={isDeleting}
      />
    </div>
  );
}
